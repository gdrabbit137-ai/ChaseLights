評分模型（v2 owner 裁示）

評分對象只評景點（place_id）：不評題材×窗、不評系統準不準。題材差異由 tier（✓○✗）承載；題材細節寫進留言文字。一人一票（user×place），選填拍攝日（時間衰減 half-life 365 天，裁決點 3）。
L／P 兩軸L=景色（這景點值不值得）、P=出片滿意度（實際收穫）。五級文案：不佳／普通／尚可／好／極佳。無出片鏈路會員的 P 權重 ×0.5（防「沒去也給低分」）。裁決點 1。
與 tier 關係評分永不參與 tier 計算——tier 是 fail-closed 物理預測（今天能拍嗎），評分是人類校正層（上次去了值不值），只在顯示層並列。
信任階梯五級：新會員 0.5 → 活躍 1.0 → 有出片紀錄（拍完推播邀評／accepted 回報鏈路）1.5 → 資深 2.0 → 策展 3.0。聚合＝貝氏平均（k=5）＋時間衰減＋簇上限。DR7 §3。
防洗分一人一票（編輯覆蓋）；24h 計入上限 3 票；同 IP/裝置簇等效票上限 2（第 3 票 ×0.25）；秒評/σ 異常 → flagged 人工審、fail-closed。冷啟動 n_eff<2 不出示任何分數、卡片不出空 chip。
推播聯動提醒窗觸發後 +3 小時「拍完邀評」push（每日 ≤1、每週 ≤3）直開評分彈窗；source=push_invite 是「有出片紀錄」級的自動來源。無推播訂閱者改用卡片邀評 pill。

回報／留言通道（一條 UGC）

三類提交rating（景點，分數公開）／report（回報錯誤，不公開＝站長工單）／comment（留言，經審公開；不帶景點＝站務留言）。同一張表、同一彈窗骨架、同一套信任防護。
錯誤類型單選六類：資料錯／位置錯／條件錯／季節時窗錯／封閉消失／其他——類型代碼即 triage 派工 routing key（data ticket / content ticket / 站長）。
審閱流程送出 → 自動篩（節流/禁詞/同簇去重）→ open 佇列 → accepted（建 ticket＋計 trust 貢獻）/ need_info / rejected。留言首審制公開（裁決點 2）。
管理端最小方案：D1 表＋現有 admin 頁骨架加「回報審閱」清單頁（篩選＋展開＋三鍵處置＋CSV 匯出），不建新系統。
舊留言退役guest-comment.js/css、index.html 頁尾區塊、GAS bridge action='comment' 分支、/api/comment 代理、cl-ui-52 測試——W1 新通道上線 → W2 並行 2 週 → W3 單票退役（可 revert）。Sheet「訪客留言」遷移入 feedback（source=legacy_import、權重 0、不公開）；legacy 四分頁 sync 分支【保留】。

UI 佈局

卡片本體原樣（DESIGN-6 定案）。唯一新增＝標題行 tier 徽章旁一枚景點評分 chip「★4.1·34」——僅達門檻組合顯示；chip 點按開景點彈窗評價區。
景點彈窗quick-look（現在去會怎樣＋24h 色帶）＋事實 pills（海拔/日出，data 層）→ 分隔線（事實｜評價） → 評價區塊：L/P 雙軸列＋P≥4 出片率＋n＋近 30 天＋匿名留言 ≤3 則（遮罩暱稱）＋「我的評分」列＋兩鈕 ✎評分／🚩回報錯誤。冷啟動＝虛線框「尚無足夠評價」＋邀評 CTA。
評分彈窗L、P 各五級按鈕（雙編碼：刻度點數＋文字），兩軸選完主按鈕才啟用；文字留言選填；匿名聲明「顯示為 晨曦**」。流程 B（推播邀評）帶「📸 今日拍攝」綠標＝出片鏈路。送出→完成態（我的評分＋再編輯入口，綠框=入聚合確認）。
回報彈窗類型六格單選（icon＋中英文雙編碼）→ 說明（必填）→ 更正建議（選填）→ 匿名聲明 → 送出 →「已收到·審閱中」（ amber 確認）。
頁尾原 CL-UI-52「💬 留言」同位置換「💬 留言／回報」開同一通道（站務留言＝不帶景點）。mockup-bar「未登入」→ 任何提交呈登入引導（新通道要求登入，honeypot 由其取代）。
色彩語義評分數字＝琥珀（--cl-amber-text）——語義色只屬於 ✓○✗，評分不用綠紅以免誤讀為 tier 判定；「我的評分」確認態用綠（=入聚合成功）；回報完成態用琥珀（=審閱中，非公開發布）。
