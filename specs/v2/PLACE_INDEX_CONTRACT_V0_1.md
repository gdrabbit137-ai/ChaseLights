# U-W4-02A — Place index v0.1

Owner W1. Normative proposed contract; adoption requires review. Schema: [place-index-v0.1.schema.json](schema/place-index-v0.1.schema.json). This is an additive W2-owned projection, not a change to Opportunity v2.1 or permission to publish. Latest main R4.2 §§7.1–7.2, Navigation and V2 Access Advisory/Free Composition policies take precedence.

## Identity, administrative membership and names

| Field | Meaning / missing data |
| --- | --- |
| `schema_version`, `index_revision` | Format `0.1.0`; opaque immutable content revision. A changed index gets a new revision. No timestamp used as a substitute for a content identity. |
| `places[].place_id` | Existing W2 `place_id` verbatim (e.g. `tw-026`, `us-071`, `jp-010`). Stable across names, translations, administrative changes and publication. New opaque IDs are allocated by W2, never derived from names. IDs are case-sensitive and never reused. Merge/split requires a reviewed explicit migration; no implicit prefix parsing. |
| `name_i18n`, `aliases_i18n` | Exact `zh-TW`, `en`, `ja` keys. A Place name is distinct from its Opportunity's composition title. Arrays of sourced aliases may be empty. Missing name is null, not an invented translation. `metadata_status=COMPLETE` requires all three names; PARTIAL/UNKNOWN retain explicit nulls. `semantic_review=APPROVED` requires external human parity review; presence checks cannot confer approval. |
| `country_codes`, `region_ids` | Set-valued membership, not one primary region. Countries use ISO 3166-1 alpha-2; regions use stable `country:TW` or `admin1:US-WA` IDs and the registry's official ISO code. Include both country and first-level subdivision membership. TW: county/city, US: state/DC/territory as applicable, JP: prefecture. Do not substitute continent, tourist region or city for admin1. Future countries are supported without a new Place schema. |
| `regions[]` | One row per stable ID: `country_code`, `level`, `code_standard`, `code`, complete three-language `name_i18n`. COUNTRY uses ISO_3166_1; ADMIN1 uses ISO_3166_2. W2 must cite and review current code/name sources; syntax alone does not verify geography. Deprecated codes need an explicit reviewed migration, not ID reassignment. |
| `admin_status` | COMPLETE: every supported-country membership has country + evidenced admin1 entries. PARTIAL: known memberships only; UNKNOWN: empty country/region arrays. No inference from ID prefix, representative weather point or current public Catalog. `evidence_refs` retains name/admin sources; COMPLETE metadata/admin requires sources. |
| `time_zone` | Shared 02B envelope: VERIFIED + IANA `iana_id` + `evidence_ref`, or UNKNOWN + two nulls. Verification is Place-scope evidence plus IANA membership, not device settings or a country default. |

Initial product registry acceptance is TW **22** county/city entries (including Kinmen and Lienchiang), JP **47** prefectures, and US **50 states + DC (51)**, independent of the number of researched Places. W2 supplies the sourced complete registry; W4 shows registered regions without eligible Places as localized “not yet catalogued,” without inventing a Place card. A partial research fixture may have a smaller registry and cannot claim complete picker readiness. Future US territories or other countries may be added explicitly; they do not change the first-phase 51-state/DC acceptance set.

A Place spanning two counties/states/prefectures or countries is **one Place** with multiple memberships. Membership describes the researched Place extent, not necessarily its photographed target or arrival point. Deduplicate by Place ID; two Opportunities at `tw-026` do not become two Places. Conflicting source identity stays withheld pending W2 review. An extent spanning time zones requires an evidenced evaluation scope or separate researched Place identity; until resolved, one arbitrary zone must not be chosen (02B UNKNOWN).

## Canonical join and publication

`opportunities[]` joins `opportunity_id` to `place_id`, exact canonical `revision`, `source_commit_sha`, `source_path` and Git `source_blob_sha`. Paths are `data/v2/opportunities/{opportunity_id}.json`. The pinned file must pass the existing Opportunity v2.1 validator; ID/Place/revision and bytes must match. Different records may have different source commits. An index row never modifies Canonical, copies an Opportunity title into a Place name, creates evidence, or overrides its review state. No fixed Catalog count is part of this contract.

`publication` is an Opportunity-level projection, derived from reviewed W2 canonical/evidence release state:

- `RESEARCH_ONLY`: explicitly initiated research workspace/preview only. Never the normal guide or a selected-date recommendation. Existing R1 preview remains a deliberate separate surface, not default UI filler.
- `GUIDE_ELIGIBLE`: verified existence, approved canonical lifecycle and reviewed evidence/crosswalk + human three-locale release approval. `publication_approval_ref` resolves an immutable W2 approval artifact bound to this exact source/revision. Partial Place names or pending semantic review cannot qualify. This says what can be photographed, not whether a selected date is suitable.
- `WITHHELD`: not admitted to either public surface (e.g. conflicting identity, invalid schema/hash or revoked approval). Retain audit data outside normal UI.

Every row has nonempty machine `publication_reason_codes`; `publication_approval_ref` is null unless GUIDE_ELIGIBLE. A Place is guide-visible only if at least one related Opportunity is eligible. Recommendation eligibility is **never** a Place-index flag: it additionally requires a genuine, date-matched, approved runtime decision under existing EvaluationResult/recommendation policy. No R1/R2/R3 number, taxonomy tag, valid date or `GUIDE_ELIGIBLE` alone creates a forecast. Access/closure notices stay prominent and non-scoring; navigation is still independently guarded.

## Selection, search and incomplete metadata

The shared browse request is [browse-query-v0.1.schema.json](schema/browse-query-v0.1.schema.json), specified with 02C. `region_ids=[]` means all; a nonempty list is OR across selected IDs. Country selection matches all Places with that country membership; no duplicated child entries are required in the request. Region filtering ANDs with topic, search and favorites filters. An unknown selected ID is INVALID_FILTER, not silently dropped. Preserve stable selections across locale changes; unknown IDs after index revision show a clear reset/reselection action.

Search: trim, Unicode NFKC, casefold, collapse whitespace; match a substring in any available localized Place name, alias, stable Place ID, associated registry country/admin1 name or code/ID, or **eligible-on-this-surface** related Opportunity name. No accent stripping, transliteration, fuzzy matching or auto translation in v0.1. Empty query matches all. Null names are skipped safely; ID search remains usable in explicit research. Do not leak withheld/research Opportunity names into ordinary guide search.

Filter first, deduplicate Place IDs, then sort. Missing admin membership cannot match a specified region; with no region filter it may remain in an allowed research surface with an honest localized missing-name/region fallback. Partial rows do not silently borrow browser locale data. A required translation missing from a purported GUIDE row invalidates the row and triggers a W2 handoff. Same-named Places retain distinct IDs and show available sourced administrative labels for disambiguation. Clearing search changes only search; region/topic/date clear actions likewise affect only their own dimension. Region-panel selections take effect immediately and remain selected when the panel closes; Done closes the panel without a second hidden Apply state. W4 owns bounded layout, focus/scroll restoration and X/Done/background/Escape/Back interactions. Zero matches is EMPTY, not ERROR and not a reason to insert unqualified Places. Explain active filters and offer clear filters. Loading/error/invalid index is not an empty success; never retain stale cards as current results.

## Acceptance

W1 structural/semantic tests cover multi-admin and multi-country membership, TW/US/JP code relationships, duplicate IDs and dangling joins, two Opportunities per Place, canonical byte/revision tampering, missing translation/source and incomplete metadata. W4/W5 must additionally exercise OR-within-region / AND-between-filters, country matching, cross-locale search/selection, safe null names, invalid filters and honest empty/loading/error states. Fixtures are synthetic contract examples or pinned research records, never new factual administrative assignments. Human review must verify code registry, Place extent/name parity and approval artifacts.
