## Decision: one provider and one Place

Use the existing V1 provider **Open-Meteo Forecast API**, `/v1/forecast`, for a **noncommercial, publicly reviewable research pilot only**. Select **Qixingtan / 七星潭 / 七星潭, `tw-036`**, with existing canonical context `tw-036-P01`. The W2 study binding is [tw-036-open-meteo.json](../../data/v2/weather-pilots/tw-036-open-meteo.json); its revision/hash is an input, not a permission to promote the public index.

The scoped purpose is personal/public noncommercial weather-information research without advertising, subscriptions or commercial promotion. Official terms admit that class of use. This does not certify the whole website's commercial status or establish paid entitlement. Stop this free-endpoint path before commercial use; a separately entitled provider configuration requires review. There is no paid purchase, new key, scheduled job or public publication in this task.

Official source review, 2026-10-19:

- [Terms](https://open-meteo.com/en/terms): free API restricted to noncommercial use, below 10,000 weighted calls/day, 5,000/hour, 600/minute; application/IP sharing matters, and availability is not guaranteed.
- [Licence](https://open-meteo.com/en/licence): API data CC BY 4.0; keep source and licence links and identify transformations next to the weather information. This is distinct from the server source-code licence. Do not copy its server implementation or V1 modules.
- [Pricing](https://open-meteo.com/en/pricing): requests over ten variables or two weeks can count as multiple calls. This pilot requests ten fields for 72 hours; budget retries too. The local binding caps eight captures/day, at least three hours apart, at most three HTTP attempts/capture. Check combined V1/application/IP usage before opt-in capture; no automatic scheduling is authorized here. On 429 obey Retry-After or stop; never immediate retry loops.
- [Forecast docs](https://open-meteo.com/en/docs), API parameters/hourly definitions/JSON response: distinguish instantaneous values from preceding-hour precipitation; epoch seconds are UTC; returned coordinates describe the selected grid, not the request point. Provider-selected models may differ by variable and be interpolated to hourly output. `generationtime_ms` is processing duration, not issue/update time.

Alternatives were inspected in existing code, not reimplemented: `jma_msm_aws_om.py` transports native JMA cloud layers from Open-Meteo's AWS data; its current SOURCE_TO_TARGET is a cloud-map product, not this ten-field time-series contract. `cwa_weathergrid_derived.py` contains experimental RH-derived cloud potentials, not interchangeable native low/mid/high cloud percentages. Neither is needed while this narrowly admitted Open-Meteo research use applies. If the scope/entitlement changes, reopen source choice; do not silently substitute JMA/CWA proxies. Himawari imagery is observational, not future hourly weather. #517 NWS is independent and not a Taiwan fallback.

## Minimal contract; preserve existing schemas

The existing `weather-source-record-v0.1.schema.json` is explicitly NOAA_NWS with NWS URLs, non-null update time and interval records. It cannot truthfully carry Open-Meteo, unknown update time or instantaneous/missing values. Keep it **unchanged**. Keep Canonical v2.1, EvaluationResult v0.1, M6a solar and shared date-query schemas unchanged. Reuse their provenance separation, local-date semantics and fail-closed policy. Add only [hourly-weather-info-v0.1.schema.json](schema/hourly-weather-info-v0.1.schema.json), scoped to this provider/Place research artifact; no new generic weather framework. It is not an EvaluationResult or an unreviewed new value of the old date-query artifact enum.

Request exactly: `latitude=24.031426`, `longitude=121.62717`, `forecast_hours=72`, `past_hours=0`, `timezone=GMT`, `timeformat=unixtime`, `cell_selection=land`, `temperature_unit=celsius`, `wind_speed_unit=ms`, `precipitation_unit=mm`, and `hourly` in the following table order. The normalized `request.coordinate_role` is provenance only: **do not send it as an API parameter**. Omit `models` and record `provider_default_auto`; single provider does not mean a single known model. No daily/sunrise/sunset, marine, history, wind direction, WMO code, radiation or scoring in this pilot. Existing V2 solar may be a later independent integration.

| Request/output key (same names) | Normalized unit | Time support | v0.1 meaning |
| --- | --- | --- | --- |
| temperature_2m | °C | Instant T | Model temperature at 2 m |
| dew_point_2m | °C | Instant T | Model dew point at 2 m |
| relative_humidity_2m | % | Instant T | Model relative humidity, not fog occurrence |
| cloud_cover_low | % | Instant T | Source low-cloud fraction, not a clear-horizon verdict |
| cloud_cover_mid | % | Instant T | Source mid-cloud fraction |
| cloud_cover_high | % | Instant T | Source high-cloud fraction |
| wind_speed_10m | m/s | Instant T | Model wind at 10 m, not measured beach/tripod wind |
| visibility | m | Instant T | Model visibility, not confirmed subject discernibility |
| precipitation | mm | (T−1h,T] | Previous-hour accumulated total precipitation |
| precipitation_probability | % | (T−1h,T] | Previous-hour precipitation probability; not photo success probability |

Eight instant fields use `valid_at_utc=T`, not an invented one-hour validity interval. The last two use row `preceding_hour.start_utc=T−3600s`, `end_utc=T` with **open start/closed end**. These endpoints represent aggregation, not the half-open NWS forecast interval. Do not shift precipitation to (T,T+1h]. For local-day selection, instant rows use Place-local date of T; aggregated values are associated with interval end T and labelled as the preceding hour, even when start lies on the previous civil day. No prorating, interpolation or synthetic values at a day boundary. General overlap queries must inspect the actual interval. Use actual IANA per-instant offsets, not `utc_offset_seconds`, for Place formatting. Example: `2026-10-19T16:00:00Z` is `2026-10-20 00:00 Asia/Taipei`; the user's literal selected date is never parsed in the browser's timezone.

### Artifact and missing-value rules

- Root identity: schema version, pilot ID, exact W2 binding SHA256, Place, verified zone and actual tzdb version; immutable source request URL/hash. Identity mismatch rejects the result rather than relabelling it.
- `data_state=RAW_ONLY`, `calibration_status=UNVALIDATED`, `recommendation_eligible=false`, `photography_verdict=NOT_EVALUABLE`. Strict objects prohibit score, Directions and success/favorable additions.
- Preserve original HTTP JSON bytes and their SHA256 before decoding; record final HTTPS endpoint, retrieval completion time, normalization time, response grid latitude/longitude and elevation. Preserve request point separately. Retain provider timezone GMT / UTC offset 0. No redirects, insecure TLS or host fallback. Bounds: 20 s network timeout and 3 MiB decompressed body; report failures explicitly. Error body/HTML is not forecast JSON. HTTP Date is transport metadata only.
- `source_update_time_utc`, `provider_issued_at_utc`, `provider_run_id`, `resolved_model_ids`, `native_resolution_m`, `native_time_resolution_seconds` remain **null**, reason `NOT_SUPPLIED_BY_FORECAST_RESPONSE`, for this response mode. `output_step_seconds=3600` is the API output cadence, not native model resolution. Preserve useful unrecognized source metadata in the raw archive without upgrading its meaning.
- A request/returned valid-time axis must be epoch seconds, finite whole hours, strictly increasing and contiguous at 3600 s. Reject duplicate/descending/gapped/invalid time axes, oversized series or a response from a different request. A shorter 1–71-row series is PARTIAL; never manufacture the absent rows or call it a complete 72-hour horizon. Empty/missing time axis yields no accepted artifact and an EMPTY/ERROR diagnostic, never zero weather. Supplied field arrays longer than the time axis are invalid; shorter/missing arrays yield per-cell unavailable values without hiding the independent fields.
- All ten field keys are required. Each cell has `value`, declared `unit`, actual `source_unit`, `state` and `reason_code`. AVAILABLE requires a finite numeric original value, matching expected source unit and null reason; booleans/NaN/Infinity are invalid. Percentages are [0,100], wind/visibility/rain nonnegative; temperatures have no fabricated climate cutoff. UNAVAILABLE requires `value=null` and MISSING_FIELD / NULL_VALUE / INVALID_VALUE / UNIT_MISMATCH. Retain the actual unit string when known. No default zero, arbitrary clipping, silent unit conversion or inferred sunny/rain-free state. Genuine numeric zero is AVAILABLE only with valid provenance/units; tests must distinguish it from missing.
- COMPLETE requires all 72 actual rows and all ten cells AVAILABLE. Otherwise PARTIAL, except stale data. Transport/parse/identity failure yields no new accepted artifact; an older artifact cannot be relabelled as the new response.
- Freshness policy: `checked_at >= normalized_at >= retrieved_at`. More than 21,600 s since retrieval requires STALE; at/below the bound may be COMPLETE/PARTIAL. This is an **operational display/cache age**, not a scientific/model-age threshold. `source_freshness=UNKNOWN` remains explicit; never present the model as freshly issued. W4 must recompute retrieval age when displaying cached data and label retrieval time rather than last model update; stale/history is visibly labelled, not shown as current. W3 future/reversed clock tests must fail safely.
- Attribution requires provider and CC BY links plus trilingual transformation notice. Limitations in all locales explicitly state raw weather, grid sampling, unknown model update and no photography forecast. Access warnings remain a separate concern; open/closed does not change weather values or their availability.

The synthetic example is a **one-row all-missing PARTIAL test fixture**, not real weather or an installed-tzdb declaration. Its source hash, grid and times are synthetic and retrieval_mode=TEST_FIXTURE. Schema checks cannot authenticate a source, prove a geographic timezone, model age or forecast accuracy.
