# UGC 長期藍圖：使用者共建的攝影氣象資料庫

> PM 維護。2026-11-10 初版。背景：owner 判定「長期來看，使用者建立的景點/題材可能是主要的」——
> 本藍圖以此終局回推，定義架構、品質、治理、經濟四個面向的完整規劃。

## 1. 北極星願景與三階段演進

**願景**：全球風景攝影師的「條件決策資料庫」——任何人可以貢獻景點與題材，品質由查證產線保證，
官方 350 點永遠是品質基準與錨點。

| 階段 | 資料供給 | 平台角色 |
|---|---|---|
| S1 現在 | 官方 350（repo） | 生產者 |
| S2 過渡 | 官方＋社群並行，官方主導流量 | 生產者＋治理者 |
| S3 終局 | **社群為主要供給**，官方點＝品質基準、錨點、示範 | 治理者＋基礎設施 |

飛輪：貢獻 → 查證背書 → 流量與署名 → 更多貢獻 → 資料庫價值（不可抄的 D1 資產）。

## 2. 產品架構（終局形態）

- **官方層**（repo）：350 景點、契約、AGLI 雙榜——品質錨點與示範。公開（引擎公開是定案）。
- **社群層**（D1，不在 repo）：使用者景點/題材——**不可抄的資產**。
- **評估統一**：條件語彙同一套（`metric/op/value/required/bonus`）。官方＝Python 管線預算；
  UGC＝Worker 端 JS 評估器（≈200 行）即時評估。**輸出 schema 完全一致**，UI 對兩層零差別。
- **題材模板庫**：官方模板＝語義規格（雲海/星空/長曝…10+ 種，含預設條件與自動調參——如 LCL=海拔−200）。
  使用者題材＝模板實例＋個人覆寫。模板升級時，跟不跟進由使用者選擇（keep/upgrade 二選一，存版本）。

## 3. 資料模型（長期，D1）

```
places(id, source: official|community, owner_user_id?, name_i18n, lat, lng, altitude,
       visibility: private|pending|published|featured, attribution, license, created_at)
subjects(id, place_id, template_id?, name_i18n, conditions_json, template_version,
         override_flag, status, created_at)
condition_sets(id, subject_id, conditions[], schema_version)        -- 條件與題材分離，利於版本化
template_catalog(id, version, kind, default_conditions, semantics_invariants)
contributor_reputation(user_id, submitted, approved, rejected, level)
edit_history(entity, patch, actor, ts)                              -- UGC 必須有帳
reports(id, entity, reason, status)                                 -- 檢舉
```

- 所有權清楚：使用者內容授權平台展示（CC-BY-NC-類條款，註冊時同意），署名永久保留。
- 軟刪除＋編輯史：UGC 的糾紛與回滾基礎。
- 官方↔社群**單向升級管道**：高品質社群點經核准可「收編」進官方 catalog（走完整查證＋AGLI），
  原貢獻者永久署名——這是貢獻者的榮譽動機。

## 4. 品質與信任階梯（審核產線的規模化）

| 等級 | 狀態 | 門檻 | 機制 |
|---|---|---|---|
| L0 | 私有草稿 | 註冊即可 | 無審查，自己用 |
| L1 | 機器驗證 | 座標反查地名＋海拔 DEM＋條件語彙合法 | 提交時自動 |
| L2 | AI 查證 | 權威源 URL＋日期（現行 provenance 制度） | 批次產線 |
| L3 | 挑戰者複查 | 三層審查配對（紅隊＋知識隔離挑戰者） | 8–10 點/輪輪替 |
| L4 | 精選/官方化 | PM＋owner 核准 | 收編進官方 catalog |

- **貢獻者信譽分**：通過率→等級；高等級走快車道（L2 自動過→抽查），低信譽慢車道＋全審。
- **公開申請 SLA 公示**（如 72 小時內查證回覆）——治理透明。
- 容量封頂：每輪審核產線固定容量，排隊不爆炸。

## 5. 評估語義治理（最關鍵的難點）

UGC 的自由度會製造語義錯誤——必須讓系統「拒絕壞語義」而不是事後人審：

1. **模板語義不變量**（machine-checkable）：夜景題材必含光線窗（−6° civil）、雲海必含 LCL 類條件、
   夕照必在黃金時段內——使用者儲存違反不變量的條件組→**儲存被拒＋三語說明**（我們「所有可見光
   題材一律需要光線窗」的制度直接編碼為驗證器）。
2. **時段合理性掃描**常態跑在 UGC（22:00–06:00 可見光＝拒收）——現行紅隊檢查項自動化。
3. **不符原因自動生成**：UGC 題材的 fail reason 由條件機械生成，禁手寫（防亂寫）。
4. 不變量清單由官方審核產線維護，隨抽查發現的盲區擴充（抽查→固化閉環的 UGC 版）。

## 6. 天氣與評估管線（UGC 的 on-demand 路徑）

- **天氣**：Worker 端呼叫 Open-Meteo（免費無 key）→ KV 快取 30 分鐘/座標 → 景點頁 7 日摘要。
- **評估**：Worker JS 評估器讀「條件陣列＋預報欄位」→ 符合/不符合＋下一窗。與官方輸出 schema 一致。
- 額度保護：免費使用者 on-demand 評估限流（如 20 查/日）；付費放寬。

## 7. 經濟與付費界線

| 能力 | 免費 | 訂閱 |
|---|---|---|
| 建私有景點/題材 | ✅（上限 3 點） | ✅（上限放寬） |
| 看天氣/評估 | ✅（限流） | ✅ |
| **公開發布** | ✗ | ✅ |
| **通知推播** | ✗ | ✅（API-03 引擎） |
| 進階圖層/歷史統計 | ✗ | ✅ |
| 官方化提名權 | — | 高信譽貢獻者 |

貢獻者激勵（通過審核＝免費會員時間）列為 M3 觀察項，早期不定。

## 8. 平台與 API 治理

- API 版本化（v1→v2）；UGC 讀寫限登入；寫入限流；防爬（KV 快取＋token 綁定）。
- UGC 公開區進 browse-index 的「社群分冊」——**不與官方混排序**，雙榜只屬於官方層
  （社群點有自己的顯示欄：查證等級＋信譽＋署名）。
- 檢舉→48 小時內複查；重複點偵測（5km geo dedupe 自動化）；抄襲官方點自動擋。

## 9. 風險與對策

| 風險 | 對策 |
|---|---|
| 錯誤資料傷品牌 | 來源標示（官方/社群＋查證等級）；L0/L1 永遠標「未查證」 |
| 法律（私有地/軍區/危險地點） | 查證制度涵蓋＋UGC 條款免責＋檢舉通道 |
| 審核負擔爆量 | 信譽快車道＋批次產線＋容量封頂＋SLA 公示 |
| 競品抄 | 資料在 D1＋網路效應＋署名綁定 |
| 模板/條件語義漂移 | 語義不變量驗證器＋版本化＋keep/upgrade 選擇權 |

## 10. 里程碑

- **M1**：私人景點 MVP（建點＋天氣頁＋模板題材＋條件編輯器＋個人評估）——CL-UGC-01 起
- **M2**：審核產線＋公開社群區（目標：公開 100+ 社群點）
- **M3**：貢獻者信譽＋精選制度＋激勵實驗
- **M4**：官方化管道＋完整治理（檢舉/歷史/授權條款）

依賴：API-01（已上線）→ API-02 會員 → 本藍圖 M1。施工票依此開。

| 8 | 數據腐朽/模板碎片化 | **採納——這是最大單點風險** | §2 增：模板版本治理＝強制遷移政策——模板退役（EOL）公告 90 天，逾期未遷移的實例自動降級為「相容模式」並標示過期；平台核心評估器只保證 N-1 版本相容，防不可逆碎片化 |

**結論（PM）**：藍圖骨架成立；最大的真風險是「UGC 自由度 vs 語義一致性」的長期張力——
防線＝語義不變量驗證器（§5）＋模板版本治理（本節 #8）雙保險，缺一即碎片化。
