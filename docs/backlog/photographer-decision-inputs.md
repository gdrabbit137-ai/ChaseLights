# 攝影師決策輸入：月相／銀心方位／拍攝方位角／車程停車

**狀態**：backlog（owner 2026-11-27 裁示）
**來源**：資深風景攝影師體驗官 2026-11-26 體檢（三條動線實測）

## 問題（實測）

以「今晚半夜開車上山拍銀河／日出」動線走完整站後，全站搜尋
「月相 / 月出 / 銀心 / 方位角 / 車程 / 停車 / 光害 / 雲海」皆 **0 筆**。

- 彈窗唯一的方位資訊是太陽：`☀ 291° / -80°`，沒有拍攝主體的方位
- 沒有「銀河」題材（只有景點名「銀河洞瀑布」）
- 地圖按鈕只丟 Google Maps 座標，沒有車程、沒有停車點、沒有最後安全下山時間
- 判斷「週五看雲海」時，只能自己比對未標示單位的 `☁️ 175m` 與 `⛰ 1450 m`

對照：資料層其實已經有 `moon_illumination_fraction`、`moon_altitude`、
`galactic_core_altitude`、`galactic_core_azimuth`（`astro_hourly`），
只是沒有在決策面上呈現。

## 提議做法

1. **月相／月照**：卡片與彈窗顯示月相圖示 + 月照 % + 月出沒時刻；
   銀河題材加「月光干擾」判定（月照 > 60% 且月高 > 20° → 標註）。
2. **主體方位**：每個題材登記「目標方位」（銀心 ≈ 南南西、日出 = 東、日落 = 西），
   與 `light_direction` 的既有方位資料交叉，卡片顯示「目標 215° / 你的視角 240°」。
3. **車程／停車**：新增 `data/v2/policy/access.json`（每景點的 driving_minutes_from_city、
   parking_note、last_safe_descent），資料未經查證就不填（寧可空白，不可捏造）。
4. **出發建議**：以「建議時段 − 車程 − 30 分鐘緩衝」算出「最晚出發時間」。

## 驗收標準

- 三條動線（銀河、雲海、跨區）都能在**不離開本站**的情況下回答：
  「幾點出發、到哪停車、目標在天上哪個方位、月光會不會蓋掉」。
- 所有新增欄位在三語都有文案；缺資料時顯示「—」而不是估算值。
- `access.json` 每一筆都要有來源註記（官方網站或實地），無來源者不得填入。

## 風險

- 車程會隨路況變動，寫死數字會誤導；建議顯示「約 X 分鐘（一般路況）」並標註時間基準。
- 方位角需要每個景點的「拍攝方向」已驗證，否則會給出錯的建議。
